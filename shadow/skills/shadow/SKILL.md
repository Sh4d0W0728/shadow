# shadow

把成熟的剪辑方法和机械步骤做成可复用流程，具体镜头与叙事仍依据用户的素材。默认 Premiere Pro；用户的软件、素材、歌词、参考片、规格和叙事优先。用户已授权的搜索、下载和本地剪辑直接执行。

## 入口与工作方式

只要求整理原始素材时，直接读 [按内容分类整理](references/organize.md)，执行扫描 → 实际查看画面 → 内容摘要与分类 → 编号复制 → 校验。已提供源文件夹与目标文件夹就开始，不要求成片规格，不运行领域路由。`scripts/organize.py` 是此流程的入口；抽帧本身不等于内容识别，不能停在计划或预览阶段。

1. 从请求中提取内容身份、用途、目标时长、画幅/帧率、素材位置、字幕语言、交付形式。只询问会改变结果的缺项；其余采用并写明合理起点。
2. 用 `scripts/profiles.py select "请求"` 按**成片目的**选细分领域，仅读取相关领域文档；再加载它的 `base_recipe` 与必要技巧。领域选用见 [类型与领域](references/domains.md)，索引为 [domain-profiles.json](assets/domain-profiles.json)。例如课程招生宣传片按宣传目的选，不能仅因“课程”一词套教学流程；活动当天快剪与完整会议演讲分别处理。候选分数不是语义判断，冲突时依据用户目的与实际素材确定主流程；空候选先查索引是否已有合适领域，仍不适合再用 `scripts/recipes.py select "请求"` 选基础 [工作流](references/workflows.md)。只读相关 [技巧卡](references/techniques.md)，不在每轮重读全库。
3. 在用户项目目录初始化素材库。工作文件、数据库、缓存和模型都放在项目或用户指定工具目录，**不写进安装后的 skill 目录**。
4. 将脚本路径替换为本 skill 的实际绝对路径。先运行 `python -X utf8 "<skill>/scripts/shadow.py" doctor`。CLI `--help` 为选项的最终依据。模块依赖及安装见 [运行环境](references/setup.md)。
5. 保存可续做的 `brief.json`、素材库、`edit-plan.md`、`timeline.json` 与验证结果。可用 `profiles.py brief <领域ID> --title "片名" --output "<项目>/brief.json"` 创建待填写的领域简报，不覆盖已有文件；明确用户规格优先于任何领域起点。续做先读已有状态，只重做受影响的步骤。

实际剪辑任务按 [从素材到成片](references/editorial-playbook.md) 推进：看素材与选段 → 搭结构 → 精剪 → 声音/色彩/文字 → 观众视角复核。剪口、停顿和采访组织查 [叙事与剪口](references/story-craft.md)；三点编辑、多机位、色彩、对白与字幕查 [Premiere 精修](references/premiere-craft.md)。仅读当前问题对应章节。知识用于产生真实选段、时间线和可复核修改；不能停在方法推荐。

参考成片、学习高播放作品或需要把参考风格用于当前素材时，读 [参考片研究与实剪验证](references/reference-study.md)，按需要选 [已检查成片案例](references/finished-films.md)。实际查看画面、核对音轨证据，再把方法对应到自己的选段和时间线；为当前关键段渲染小样。`scripts/analyze_reference.py` 可静音准备接触表、场景候选与音轨测量；候选不是已确认剪点，测量不是听感。

## 1. 项目与素材准备

原始视频需要按内容整理到指定文件夹时，先按 [分类整理流程](references/organize.md) 完成实际识别与归档。默认复制并保留源目录，疑难项单列待复核；再导入后续剪辑素材库，携带原文件映射和内容笔记。

拷卡、命名和归档查 [公开教学知识库 MS07–MS08](references/mediastorm.md)。完整拍摄源包与分类工作副本分别管理：源文件名、卡目录和附属文件保留；编号只作用于工作副本。视频分类目录不算整卡备份，哈希一致也不等于视频可解码。

读 [素材库](references/asset-library.md)，运行 `assets.py init "<项目>"`。导入保留原文件；记录来源、哈希、媒体参数、标签、授权附件、候选/验证/入选状态和实际用途。同一文件去重时保留多条来源。

需要补素材时读 [包图网接入](references/baotu.md)。先按镜头缺口写检索词：主体、动作、景别、运镜、时间、色调、横竖版、时长。通过当前可用的浏览器能力操作 ibaotu.com：复用登录会话，未登录才打开登录入口并请用户完成验证；不要读取或保存密码、Cookie、令牌。正常会员下载后取得实际本地文件，安全解包、核验再入库。预览、水印视频、原片、授权文件分别记录，不能把预览当原片。

抽样观看接触表、关键片段并听取音频，写可追溯的内容摘要和可用入出点。文件名、ffprobe、场景变化和静音检测只是线索；未观看的语义必须标为未验证。`assets.py` 负责机械整理，Codex 负责基于实际画面的总结。

## 2. 叙事、选片与时间线

按主配方确定开场、发展、转折与收束；口播/采访以完整语意为先，教程保证因果，MV 先读取实际歌词与音乐情绪，电影混剪保持人物与动作关系。记录每个镜头的叙事作用、入出点和声音选择。

需要镜头意义、蒙太奇或情绪设计时，查 [公开教学知识库 MS01–MS04](references/mediastorm.md)；宣传片、预告片和活动快剪重点查 MS03–MS04。先标注素材中真实的信息点与情绪点，再决定镜头密度和停顿。重要剪点在 `edit-plan.md` 记录“素材/源时间 → 新增信息或情绪 → 与前镜关系 → 切换/停留理由 → 待核验”。教学保留操作因果，纪实核验同时性与反应来源。只记录对当前片子有用的决定，不为套卡堆效果。

将实际选中的素材写入 [timeline v2](references/timeline-v2.md)。源秒数与序列帧数不同，按实际帧率量化并核对总长。转场占用相邻镜头的重叠时长，不能把两段直接相加后再塞入转场。

转场默认硬切。只有时间/地点变化、回忆、情绪延展、章节结束等理由才用叠化或淡黑；动作、视线、构图和声音连续性通常比花哨特效更自然。叠化常从 0.3–0.8 秒起步，实际以运动重影、节奏和音频试听为准。J/L-cut、速度坡度、复杂关键帧、稳定和精细调色按技巧卡通过已验证的 Premiere 控制执行，不能在 JSON 中编造未知字段。

## 3. 音频、文稿与字幕

读 [字幕流程](references/subtitles.md)。先从**剪辑后的序列音频**识别；若在原素材上识别，必须按剪辑入出点和转场重新映射时间后才可用于成片。不能用字数平均分配时间来冒充识别。

`subtitles.py transcribe` 使用本地 faster-whisper 获得时间戳；用户文稿辅助标点、术语和文字核对。默认保留有实质差异的识别结果并报告待复核项，特别检查人名、数字、否定、歌词和重叠说话。无语音片段不强插文稿。保留识别 JSON、校正报告、UTF-8 SRT；可另导 ASS。

字幕定时以可读性和语意断句为准；两行以内是常用起点，不切开人名或固定短语。SRT 不携带字体与位置；样式记录在时间线/ASS，PR 中另设字幕轨道样式。文本修改后同步更新 SRT/标题配置与成片。

## 4. 标题、声音与成片

在时间线 `titles` 中设置片头、章节字和人物介绍的文字、时间、位置、大小和颜色。检查中文字体、留白和安全区域；标题与对白字幕避免遮挡。脚本渲染可用透明文字图层，在 PR 交接中说明文字是可重新生成的图像素材还是实际可编辑文字。

明确保留/静音源声音，设置音乐起点与增益，检查是否覆盖所需时长。按语音可懂度调整背景，试听剪口爆音、叠化与峰值；不能仅凭波形宣称声音合格。

人声忽大忽小或被音乐遮盖时查 [公开教学知识库 MS05–MS06](references/mediastorm.md)。根据实际动态决定压缩、增益与闪避，示例参数不是通用预设。研究教程优先读取公开字幕与文字；浏览器保持静音，不自动外放。用户要求静音时可继续转录、测量和规划，但未试听的结果标记为待听感核验。

执行 `shadow.py validate` 后生成 XML 和预览。先小样验证风格，再按要求渲染成片。基础命令见 [命令说明](references/commands.md)；可用 [流水线助手](references/pipeline.md) 把粗剪、序列音频识别、字幕合成和 XML 交接串联起来，任一失败会保留阶段报告。

## 5. Premiere 与交付验证

读 [Premiere 交付](references/premiere.md)。XML 与独立 SRT 一并交付；若具备桌面控制且要求原生工程，在 PR 新工程中导入，检查媒体、转场、字幕和文字后另存 `.prproj`，重开验证。不能改扩展名冒充原生工程。

- 内容身份：用户请求、歌曲/艺人、音频、歌词、素材、工程、成片和交付名称一致，不静默替换。
- 结构：媒体存在，入出点有效，帧率/画幅/总帧数正确，音轨和字幕与序列对应。
- 成片：全片解码，检查实际参数；抽看首尾、剪口、标题、字幕，听取代表性声音。必要时检查响度/峰值和字幕可读性。
- PR：只有实际完成导入、播放、保存/重开才报告验证通过；结构通过不能代替 PR 实测。
- 交付：根据请求提供视频、PR 工程/XML、SRT、素材清单、创作说明和核验报告。请求成片时不能只给方案。

输出新文件、保留原素材和原工程。会员下载权限与页面显示的使用范围如实记录；无需为已授权的普通下载反复确认，但不自行付费升级或接受新的合同。给出实际完成范围与尚需人工审美复核之处，不承诺零思考或固定节省比例。
