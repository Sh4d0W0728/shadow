# 从素材到成片：判断、执行与复核

本页是 shadow 的原创执行框架，用于把已学方法落实到实际素材。教学依据按需查 [叙事与剪口](story-craft.md)、[Premiere 精修](premiere-craft.md)、[影视飓风公开教学](mediastorm.md)，基础手段查 [技巧卡](techniques.md)。不必每轮读取全部文档。用户只要整理素材时走 organize 流程，不强加以下成片步骤。

## 1. 先确定这条片子要完成什么

读已有 brief、参考片和素材，写一句“给谁看、让他理解或感到什么、看完需要什么”。用户只有“剪好看”时，先根据真实素材提出可执行的主线并推进；仅询问身份、交付目标等确实影响结果的缺项。用户指定的歌曲、时长、比例、字幕和必留内容进入约束清单。

参考片拆成可观察的特征：信息怎么进入、镜头何时变化、音乐何时退让、色彩关系、文字层级与结尾感受。只借适合本次素材的组织方法，不照搬别人的文案、角色关系或素材缺口。

## 2. 看清素材，再建可用镜头库

沿用素材整理的真实抽帧和来源映射；对于候选镜头，补看动作前后、句子上下文和真正入出点。每条选段记录：

| 字段 | 要回答的问题 |
| --- | --- |
| 来源与时间 | 是哪个文件、哪一段？可返回原片核对吗？ |
| 可见内容与原声 | 画面实际发生什么？声音是否已听核？ |
| 叙事用途 | 交代环境、解释动作、提供证据、呈现反应还是收束？ |
| 入选理由 | 新信息、清楚动作、真实情绪、视觉呼应中的哪一项成立？ |
| 可用限制 | 焦点、遮挡、抖动、噪声、方向、色彩、原声完整性怎样？ |
| 余量与备选 | 选段两端还有多少素材？替换镜头在哪里？ |

先挑“服务这条片子”的镜头，再比较同功能镜头的清晰度和表现力。不要仅按分辨率或画面漂亮程度排序。没有依据的情绪和人物关系保留未知；接触表不等于完整观看。

将缺口分成两类：必须由真实记录提供的事实/反应/过程；可以用授权库存、图形或标题解释的背景。再按 [包图网流程](baotu.md) 补材。素材不足以达到指定时长时先核算；不能把重复、无依据慢放或长黑场当默认填充方案。

## 3. 先搭结构，再决定剪点

在 `edit-plan.md` 写段落功能和对应选段，建立能理解的粗剪。需要压缩时先去重复信息，保留关键条件与原意；需要增强时补证据、动作或落点，不先堆转场。只有明显存在两种可行主线时，做两份简短结构比较并选择更符合 brief 的一份，不要求用户为每步审批。

| 类型 | 优先组织 | 必查的失败方式 | 按需阅读 |
| --- | --- | --- | --- |
| 品牌/产品宣传 | 受众问题、实际行动/证据、主价值和落点 | 只有口号或漂亮镜头，观众仍不知道是什么 | MS03–04、ST02、PR03 |
| 活动快剪/回顾 | 必留人物与事件节点、现场声、情绪起伏 | 漏掉关键环节、把无关反应接成事实、错过截止 | MS01、ST01–02、PR02 |
| 网络课程/录屏 | 前提、步骤、参数、结果与验证 | 为悬念隐藏操作条件；字幕或标题遮住关键操作 | MS02、PR01、PR06 |
| 采访/纪实 | 完整观点、真实证据、人物行动及上下文 | 拼句改变原意，借用异时异地反应制造因果 | ST03、MS01、ST01 |
| 歌词 MV/音乐混剪 | 实际歌词与乐句、意象发展、情绪释放 | 每拍必切、意象只有字面对应、整片强度一样 | MS02、MS04、ST02、ST04 |
| 婚礼/人物故事 | 可核验的关系、关键原声、细节与回响 | 只剩音乐和空镜，失去当事人自己的声音 | ST03、ST01、MS04 |

拍点和镜头长度只是候选切点。重要剪点记录“来源/时间 → 新信息或情绪 → 相邻镜头关系 → 切换或停留理由”。动作、句意或反应尚未完成时先保留；连续运动与对白先试硬切，确有时间、空间或情绪转换再加转场。静音状态可检查视觉逻辑，不能把它记为节拍或音频验收。

## 4. 按问题做精剪，不按特效清单做片

一轮只解决一类问题，避免反复重做已经通过的部分：

1. **故事轮**：脱离解释文字是否还能理解主线？每段是否提供新内容？删掉一个镜头会失去什么？
2. **剪口轮**：关键句前后、动作相位、视线、主体位置和方向是否自然？调整真实入出点；必要时用相关插入镜头或音画分离剪辑。
3. **节奏轮**：哪些位置需要观众看懂，哪些可以加密？重点前后是否有呼吸？同一段比较一两个有目的的版本即可，不机械试所有效果。
4. **声音轮**：先对白与同期主线，再环境与音乐，最后必要音效。查 PR04–05 与 MS05–06；处理前后保持可比较的感知音量。遵守静音指令，未听核的内容列出待验时间点。
5. **色彩轮**：先确认源与序列色彩处理，匹配镜头，再统一风格。不要用未知 LUT 叠加纠正已经发生的错误变换；查 PR03。
6. **文字轮**：一个主信息、清楚层级；字幕按最终时轴和用户文稿核对，尤其数字、姓名、否定和术语。检查字幕、标题与主体是否互相遮挡；查 PR06。

每轮在计划中记录“问题时间点 → 修改 → 复核结果”。结果可为通过、待验证或无法由现有素材修复，不填写没有依据的审美分数。需要用户审风格时交实际小样，同时继续不依赖该反馈的机械准备；已授权的流程不因小样而默认停工。

## 5. 把决定落到现有工具

- 镜头顺序、源入出点、静态照片、基础音乐增益、支持的叠化/淡黑、图片标题和字幕按 [timeline v2](timeline-v2.md) 写入真实字段。重叠影响总时长，最终帧数要重新核算。
- J/L-cut、任意多轨混音、压缩、Ducking、复杂变速、多机位和精细调色使用实际可用的 Premiere 控制完成；无法操作时交明确的时间点与参数建议，并准确说明尚未应用，不能在 JSON 里新增想象字段。
- 标题 PNG、独立 SRT、原生可编辑文字是不同交付；按用户需要准备。导入原生字幕后避免再显示一层图片字幕。
- 请求成片就继续渲染、解码、审看并交付实际视频；只写知识卡或剪辑计划不是该类任务的完成条件。

## 6. 最后从观众角度复核一次

按实际投放尺寸观看，而不是只在全屏编辑器判断字大不大。核对内容身份、信息和情绪目标、用户必留项、视觉连贯、语言可懂度、色彩一致、字幕同步与结尾是否完成任务。再执行技术验证和 [Premiere 交付](premiere.md)，分别报告实际做过的检查。

发现局部问题只回到对应一轮修复；结构问题则回到选段和主线。好的成片需要真实素材上的取舍与复核，不能由卡片数量、固定节奏公式或一次导出成功来判断。
