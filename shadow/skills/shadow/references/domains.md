# 按片子用途选领域

领域决定取舍，基础配方提供剪辑手法。先读用户本次用途，再选一份主领域文档；需要跨类型交付时建立多个输出版本，共享素材库，而不是把全部流程混进同一条时间线。

```powershell
python -X utf8 "<skill>/scripts/profiles.py" list
python -X utf8 "<skill>/scripts/profiles.py" select "活动当天交付60秒竖屏快剪，保留获奖者与关键仪式"
python -X utf8 "<skill>/scripts/profiles.py" show event-same-day
python -X utf8 "<skill>/scripts/profiles.py" brief education-course --title "第1课" --audience "初学者" --duration 600 --aspect 16:9 --fps 25 --output "<项目>/brief.json"
```

`select` 只返回关键词候选、命中词和冲突信号，不自动批准选材或渲染。没有匹配时退回 general-story；目的明确时优先遵循用户，模糊且会改变交付时再询问。`show` 返回所需输入、交付与验收要点、领域文档路径。`brief` 创建可续填 JSON，保留用户明确指定的时长/比例/帧率，其余留空；它不是完成的创作方案，更不能直接作为剪辑时间线输入。

## 三个容易选错的场景

- “活动当天快剪”围绕现场高光、截止时间和必留人物建立最短交付链，按已核验镜头先出小样；“活动完整回顾”需要阶段、关系和情绪的发展；“完整会议演讲”保留论证与演示信息，不能只按音乐节拍剪。
- “网络课程”优先知识依赖、步骤准确与可读停留；“课程招生宣传片”优先受众痛点、课程收益证据和报名行动。题材相同而目的不同，使用不同领域。
- “企业宣传片”需要组织身份、能力证据及可信人物场景；“产品发布视频”围绕具体使用结果与差异证据。包图库存可补环境、氛围与示意，不能冒充企业实景、活动记录或实测产品效果。

## 开始到交付

1. 选主领域，读取索引中 `reference` 指向的文件；按 `base_recipe` 用 recipes.py show 获取核心技巧。
2. 将领域所需输入与用户现有素材核对。缺少真实事实/必留镜头时记录缺口，库存搜索只补适合的镜头。
3. 简报记录目标受众、身份、用途、必留内容、交付规格。镜头选择与转场理由写进 edit-plan；执行字段仍以 timeline-v2 为准。
4. 通用素材/字幕/标题/渲染步骤沿用 SKILL.md。领域中的精细调色、遮罩、屏幕强调等若未被运行层支持，交由实际 Premiere 操作并验证，不发明脚本字段。
5. 用领域 `quality_gates` 与用户验收标准检查结果，再记录程序验证、实际画面/声音检查和 PR 验收各自的完成状态。

新增领域时维护 [领域索引](../assets/domain-profiles.json) 与对应独立文档，并运行仓库验证与路由测试。成熟脚本无需按领域复制一份。
