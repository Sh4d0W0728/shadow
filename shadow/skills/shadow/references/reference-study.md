# 从参考成片到实际剪辑

用于用户给参考片、要求学习高播放作品，或已有素材需要确定风格的任务。已检查的案例见 [成片案例](finished-films.md)；常规叙事方法继续用 [从素材到成片](editorial-playbook.md)。

## 选择与取证

优先选与本次任务有相同传播目的、素材条件或情绪转折的作品。高播放量是筛选线索，不证明某种剪法导致成功；保留原作者/发布者、链接、播放量及抓取日期。分 P 视频记录实际研究的页码和 CID，不能把合集总时长当单片时长。

取得可合法访问的本地参考文件后，先确认下载完整、视频可解码。网页标题、评论、教程讲解、封面、候选剪点及自动摘要均不能代替查看成片。通过公开 API 获取资源时遇登录或访问限制就使用正常授权入口；不导出 Cookie 或分享短期签名地址。工作媒体、账号会话、抽帧和全文转录放项目目录，不装进插件或上传公开仓库。

## 静音分析工具

`analyze_reference.py` 只读取本地文件，不启动播放器；需要 Python 3.10+ 标准库、FFmpeg 与 ffprobe，不额外依赖 Pillow，不写入插件目录。

```powershell
python -X utf8 "<skill>/scripts/analyze_reference.py" "<项目>/参考片.mp4" --out "<项目>/reference-analysis/第一次" --interval 3 --pairs 24
```

FFmpeg/ffprobe 可用 PATH、`SHADOW_FFMPEG` / `SHADOW_FFPROBE` 或对应 `--ffmpeg` / `--ffprobe` 参数指定。输出目录必须尚不存在。具体参数以 `--help` 为准。

输出含媒体信息与哈希、覆盖全片的带时间点接触表、场景变化候选和前后帧、逐秒 RMS/采样峰值、近静音区间。实际查看接触表，再对关键段加密采样或逐帧验证；`--times` 可补关键秒点。记录已查看范围和采样间距，不声称逐帧看完全片。

所有时间使用原始 PTS 减 `format.start_time` 后的媒体相对秒。总时长与实际视频区间分别记录在 `duration_seconds`、`timeline`；音频先开始时，不能用视频自身长度充当媒体终点。指定秒点须在实际视频区间，前后帧同时记录请求秒点、seek 秒点和实际解码秒点，接触表标实际解码时间。只对第一视频/音频流做全片解码；音频电平表排除声明音轨终点之后的 AAC 填充尾部，排除量另有记录。

两项容易造成误判：同色正反打可能完全漏过场景阈值，闪光或快速运镜也可能误报剪点。因此候选数不是镜头数，候选间隔不是平均镜长。混合音轨 RMS 不区分人声、音乐与音效；不是 LUFS、节拍或音乐情绪。保持用户要求的静音，未听取的声音美感、配器、爆音与可懂度标待核验。ASR 错词需对照画内字幕或可靠文稿，不能把 tiny 模型输出直接写成作者台词。

## 把观察变成编辑决定

在 `brief.json` 的 `editorial_decisions.reference_studies` 或 `edit-plan.md` 只记对当前片子有用的映射：

| 项目 | 应写的内容 |
| --- | --- |
| 来源证据 | 案例 ID、URL、源时间段、实际看到/测到什么、采样或听取范围 |
| 学到的方法 | 信息怎样推进；密与疏怎样交替；文字承担什么职责；何处用声音或停顿连接 |
| 本片条件 | 自己哪段素材的入出点、动作、视线、表情或声音满足这个方法 |
| 时间线决定 | 镜头顺序与时长、保留/删除理由、标题和字幕时点、音乐段落；只写受支持字段 |
| 验证结果 | 实际渲染后的观察，若做对照写 A/B 差别；未听音/未进 PR 的部分如实保留 |

例如从“片尾回收片头动作”迁移时，先找到本人素材中确实可互相回应的两段；没有就选明确的结果镜头收尾。不能为了套案例把不同时刻的反应伪造成现场因果。复制参考片的音乐、画面、字幕设计或精确剪点，并不等于学会它。

## 用小样检验，而非堆技巧

从用户素材中选一个有代表性的短段，按需要做两种可比较的版本：例如等长顺排与“铺垫—加速—落点”对照，或删掉反应与保留反应对照。保持素材、总长等无关变量尽量一致，解释改动的目的，实际渲染并查看关键帧/剪口。小样长度服从用户期限和片子类型，不每次强制双版本。

每次延长停留要有可见目标：人物进入、动作完成、表情改变或观众读懂信息。渲染后确认目标发生且没有过长空等；发现信息过挤就调整实际时长，不只修改说明文案。成片素材自带的字幕、音乐与原有剪口会限制重剪，不能将成片摘选练习当作原始素材剪辑验收。

v2 时间线能实施选段、排序、硬切、叠化/过黑、静态音量、独立音乐、标题和字幕。J/L-cut、变速、跟踪、复杂分屏、动态图形、音乐动态闪避及精细调色仍依赖已验证的 Premiere 操作，不编造 JSON 字段。方法适用但素材或执行能力不足时，把缺口交代清楚并采用能实际实现的方案。

验收分别回答：故事是否更清楚；目标情绪是否有画面支撑；字幕是否抢注意力；节奏变化是否落在信息或情绪变化上；声音是否实际听过。渲染成功只证明文件生成，不能证明剪得更好。研究结论以可更新的案例与项目记录保存，不能说成基础模型已经重新训练。
